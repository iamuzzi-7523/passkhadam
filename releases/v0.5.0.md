# PassKhadam v0.5.0 — Credential Issuance & Governance Reliability Patch

### Summary
PassKhadam v0.5.0 resolves critical production and desktop issues identified in the decentralized credential issuance workflows and administrative governance operations. This patch preserves all v0.4.0 cloud-staging and verifiable credential architecture while restoring end-to-end functionality for employer trade credentialing, official government credential issuance, active category scope suspension, and sandboxed desktop officer governance.

### What's New & Fixed in v0.5.0:
1. **Employer Portal — Trade & Experience Credential Issuance (Fixed Loading Loop)**:
   - Resolved an unhandled reference exception (`setErrorMsg`) that previously triggered immediately upon clicking "Issue to Worker Wallet", leaving the button permanently locked in an infinite spinning loading loop.
   - Introduced localized credential error handling (`credError`) and inline modal feedback banners for instant diagnostic reporting.
   - Added `ADMIN` role parity in `backend/app/api/endpoints/employer.py` allowing platform administrators to issue or test trade credentials seamlessly.

2. **Government Portal — Verifiable Credential Blockchain Anchoring (Fixed "Failed to fetch")**:
   - Fixed route dependency resolution in `backend/app/api/endpoints/government.py` (`POST /credentials/issue`) which incorrectly typed `current_user` as `DBGovernmentOfficer`, causing an unhandled `AttributeError: 'DBGovernmentOfficer' object has no attribute 'organization_address'`.
   - Added unified user and officer profile resolution supporting both `DBUser` and `DBGovernmentOfficer` callers.
   - Implemented a FastAPI global exception handler in `backend/app/main.py` that serializes all server errors into standard JSON responses (`{"detail": ...}`), guaranteeing that Starlette CORS headers (`Access-Control-Allow-Origin`) are preserved on error responses and eliminating opaque browser "Failed to fetch" network exceptions.

3. **Admin Portal — Employer Active Category Scope Suspension (Fixed "Failed to fetch")**:
   - Resolved missing HTTP method authorization in `backend/app/main.py` by adding `PATCH` to the CORS `allow_methods` configuration (`["GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"]`).
   - Added route aliases (`POST /category-requests/{req_id}`, `POST /category-requests/{req_id}/suspend`, and `POST /suspend-category/{req_id}`) in `backend/app/api/endpoints/admin.py` to ensure high-availability compatibility across restricted network environments.
   - Enhanced `submitSuspendCategory` in `AdminPortal.jsx` with an automatic `POST` fallback if `PATCH` requests encounter client-side environment restrictions.

4. **Admin Portal — Government Officer Suspension (Replaced Blocked Window Prompt)**:
   - Eliminated reliance on browser/Chromium `window.prompt()`, which is disabled by default in Electron sandboxed desktop execution environments (`PassKhadam-Portable-*.exe`) and caused clicks to fail silently without dispatching network actions.
   - Built a dedicated, accessible React modal dialog (`Suspend Officer Modal`) featuring officer profile context, authority hierarchy verification, and a mandatory suspension reason textarea.
   - Clarified action controls: officers with `SUSPENDED` status offer single-click "Reactivate", while active or provisioned officers present the secure "Suspend" workflow.

5. **Runtime & Desktop Connectivity Resilience**:
   - Updated `apiFetch` in `frontend/src/utils/api.js` to normalize both Electron desktop bridges and web-hosted `VITE_API_URL` endpoints.
   - Bumped version manifests across `frontend/package.json`, `backend/app/core/config.py`, and executable packaging scripts to `v0.5.0`.
   - Preserved all v0.4.0 GitHub release artifacts and tags completely intact.

- Frontend production bundle: Compiled cleanly with Vite 6.
- Invariant preservation: Category decoupling, audit immutability, and worker DID provenance verified.
